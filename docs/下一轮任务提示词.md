### 2. ~~`npm run e2e` 的结构性弱点~~ ✅ 三项全修

- ~~**端口是抢占来的**~~ ✅ 已修：改为 `--port 0` 让 OS 分配，子进程把**实际**端口写进启动日志，E2E 从中读取。顺带发现并修了 `server.ts` 打印**请求端口**而非实际绑定端口的缺陷（`--port 0` 时会记出 `ws://127.0.0.1:0/ws`，调用方无从得知真实端口）。
- ~~**优雅停机零覆盖**~~ ✅ 已修（且挖出真 bug）：拆解逻辑抽到 `src/graceful.ts` 并由 `graceful.test.ts` 全平台覆盖。**原实现把兜底定时器排在所有拆解步骤之后**——任何一步抛错就 reject（信号处理器是 `void shutdown()`，成了未捕获拒绝），兜底没建、`server.close()` 没调，**进程永久挂死**。Windows 上真信号链路无法测，E2E **显式 SKIP 并说明原因**，不冒充通过。
- ~~**诊断靠日志字符串匹配**~~ ✅ 已修：`knowledge`/`skills` 的断言改为调用 `/capabilities`（文档化契约，且数据源正是写进系统提示词的那份清单）。仅剩「停机日志」与「读端口」两处必须读日志，前者本质就是查日志行为。
- 另修一条**自身竞态**：「停机后端口已释放」原是单次瞬时判定，进程刚退出时 listener 可能还没被 OS 收走 → 偶发假红。改为轮询。

### 2c. 结论：脚手架侧无遗留项

## 五、硬性约束（违反即返工）

### 安全
1. **路径校验一律 fail-closed**：`realpath` 失败就拒绝，不放行。字面路径在目录内 ≠ 真实路径在目录内。
2. **不重复实现 SDK 已有的路径/ID 逻辑**：会话目录要问 SDK（`SessionManager.create(cwd).getSessionDir()`）。
3. **新增对外端点用 `AppError`**，不手写 try/catch；`internal` 默认隐藏内部细节。
4. **重资源端点加进 `DEFAULT_RATE_RULES`**；探针类不限流。
5. **鉴权只能挂父应用**：`createApp()` 之后或 `configure` 里加中间件都无效（内核路由先注册）。
   正确写法见 `docs/嵌入指南.md`。这条已经踩过一次，不要改回去。

### 测试
6. **等条件，不要等固定时长**：用 `src/test-server.ts` 的 `waitFor(谓词, "说明")`，禁止 `await sleep(300)`。
7. **测试要真能捕获它声称防的东西**：新增测试后做**反向验证**（改回缺陷形态确认测试变红）。
   **本轮踩过的坑**：用「改索引文件名」当反向验证是无效的——读写都改了名，功能照样好。破坏点要选在**只影响一侧**的地方。
8. 不依赖网络与真实 API Key；起子进程测 stdio 协议可以，但**必须回收**（`cleanup` + `process.on("exit")`）。
9. 测试里**不要**写 `server.listen(0, host, resolve)`——回调签名不带错误参数，端口失败时 Promise 永不 resolve。用 `listenExistingServer()`。
10. **子进程必须真杀掉并等它退出**（`once("exit")`），否则端口不释放 → 下一个进程 `EADDRINUSE`。本轮踩到。

## 六、纪律（这个项目最常见的失败模式）

**不要照文档推测代码现状。** 之前连续三次说错：
- 说 `capabilities.commands` 是死字段 —— 实际有 `DEFAULT_COMMANDS` 来源
- 说审批规则缺 `glob`/`contains`/`prefix` —— 实际六种匹配器全都有
- 说存在 `registerCommands()` 函数 —— 实际是把 `commands` 传给 `attachWebSocket`

**每一条关于「现状」的判断，都要自己 grep / 读代码确认。**

另外：
- 声称「已完成」前问自己：**这条路径真的被调用了吗？**「声明了但没接线」是这个项目反复出现的缺陷模式。
- 不要把编译期的东西说成运行时的（`defineCommand()` 只给编译器看，**运行时不校验 payload**）。
- 汇报里不要写不存在的函数名。
- **改动不要提交**，由用户提交。
