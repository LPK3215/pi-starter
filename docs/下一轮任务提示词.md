## 四、这一轮做这 4 件

### 1. 真 E2E（最重要）

现在**没有任何测试真正重启过进程并恢复对话**。`src/sessions/resume.test.ts` 是同进程内模拟。

要做的：
- 起真实 Web 服务（`createApp` + `attachWebSocket`）→ 用 WS 客户端连上发一轮对话
- **让对话真正落盘**：SDK 只在出现 assistant 消息后才写 `.jsonl`，所以需要让对话跑完一轮。
  可以用**假LLM 服务**（本地 HTTP server 实现模型接口）来产生 assistant 消息，从而不依赖真实 API Key
- 杀掉进程 → **重新起一个进程** → 加载索引 → `open_conversation` 恢复 → 断言消息历史一致
- 至少覆盖：重启后能列出、能看到历史消息、已删除的对话不复活

**先验证假 LLM 服务这条路走得通**（SDK 走 pi-ai，需要匹配它的请求/响应形状）。走不通就改用「子进程 + 预置 jsonl 文件 + 真实 SessionManager.open」的方案，并在报告里说明为什么不用假 LLM。

### 2. Windows 上的符号链接覆盖

`src/sessions/store.test.ts` 有一条符号链接用例在 Windows 被 `t.skip()`（本机无开发者模式建不了 symlink），只靠 CI 的 Linux 兜。

要做的：加一个 **junction（目录链接）变体**——Windows 无需管理员即可创建目录 junction，用它覆盖「链接指向目录外被拒」这条路径，让本机也能验。

### 3. CI 的 `npm audit` 真正生效

`ci.yml` 里已经指向公共 registry（`--registry=https://registry.npmjs.org`），这步已完成。

要做的：确认它**不再被绕过**，且当前依赖树 audit 干净。已修：`proxy-addr`、`undici`、`brace-expansion` 三个传递依赖用 `overrides` 升到安全版本（见 `package.json`）。你要做的是跑一次确认 0 漏洞。

### 4. 上下文主动压缩入口

**先读代码确认**：`session-hub.ts` 里 `compaction_start` / `compaction_end` 只是**被动发notice**（SDK 自动触发时告知前端），我们**没有**主动触发压缩的工具或命令；`context/budget.ts` 只有预算估算与裁剪计划。

要做的（成本可接受就做，做不了就如实说）：

- 与现有的预算裁剪形成两级策略：**自动裁剪是常态，压缩是人工触发**，不要把两者混为一谈

## 五、硬性约束（违反即返工）

### 安全
1. **路径校验一律 fail-closed**：`realpath` 失败就拒绝，不放行。字面路径在目录内 ≠ 真实路径在目录内。
2. **不重复实现 SDK 已有的路径/ID 逻辑**：会话目录要问 SDK（`SessionManager.create(cwd).getSessionDir()`）。
3. **新增对外端点用 `AppError`**，不手写 try/catch；`internal` 默认隐藏内部细节。
4. **重资源端点加进 `DEFAULT_RATE_RULES`**；探针类不限流。
5. **鉴权只能挂父应用**：`createApp()` 之后或 `configure` 里加中间件都无效（内核路由先注册）。
   正确写法见 `docs/嵌入指南.md`。这条已经踩过一次，不要改回去。

### 测试
6. **等条件，不要等固定时长**：用 `src/test-server.ts` 的 `waitFor(谓词, "说明")`，禁止 `await sleep(300)`。
7. **测试要真能捕获它声称防的东西**：新增测试后做**反向验证**（改回缺陷形态确认测试变红）。
8. 不依赖网络与真实 API Key；起子进程测stdio 协议可以，但必须回收。
9. 测试里**不要**写 `server.listen(0, host, resolve)`——回调签名不带错误参数，端口失败时 Promise 永不resolve。用 `listenExistingServer()`。
