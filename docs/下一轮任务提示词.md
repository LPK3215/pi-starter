## 四、要做的 5 项（按此顺序）

### 1. MCP 工具桥

把外部 stdio MCP 服务器的工具接入 Agent 会话。

- **SDK 不自带 MCP 客户端**（已核实：`pi-coding-agent` 里 0 命中），需要自己接 stdio 客户端。
- 参考实现规模：`mcp-bridge.ts` 约 635 行 + 热重载。
- 要点：
  - 配置来源用 `settings.ts` 的声明式 schema（加字段时 schema / 默认值 / 持久化 / 校验自动跟上）
  - **配置改完热生效，不重启**（读配置 → diff → 只接入新增的、断开移除的）
  - MCP 工具注册进 `ToolRegistry`（带 `source: "dynamic"`），要能被 `set_tool_enabled` 开关
  - 子进程生命周期归 `addDisposer()`，停机时必须回收（否则泄漏 stdio 子进程）
- 验收：MCP 工具出现在能力目录、可被调用；改配置即生效；停机无残留子进程；MCP 服务器崩溃不影响主进程。

### 2. 计划模式（会话级「只规划、不实施」）

- 参考：`plan-mode.ts` 约 428 行。
- 要点：
  - **硬闸门**：写类工具（write / edit / bash 等）在计划模式下被拒，**拒绝原因要可操作**（模型要能据此自我纠正）
  - **软约束**：计划模式的系统提示词段落（禁代码倾倒、小需求短计划）
  - 状态随对话转录落盘（重启后仍生效）
  - 用 `src/extensions/` 的钩子接入（`tool_call` 拦截 + `before_agent_start` 改提示词），**不要改内核**
  - 新增 `settings.planMode` 字段走声明式 schema
  - 暴露为 WS 命令 + 能力目录里的状态
- 验收：计划模式下写类工具被拒且原因可读；只读工具正常；关闭后恢复；重启后模式保持。

### 3. 子代理

主对话把子任务派发给独立对话执行，结果回传。

- 参考：`subagents.ts` 约 926 行。**代码核实：`subagent` / `delegate` 当前 0 命中，确实没做。**
- 要点：
  - 复用现有的 `SessionHub` / `ClientSession` / `Conversation` 三层，不要另造一套编排
  - **子代理不占主对话的 LRU 额度**（`maxOpenConversations` 按会话计，子代理要排除）
  - 子代理失败必须**通知主对话**，不能静默丢结果
  - 结果回传要有大小上限（子代理输出可能很大，直接灌进主上下文会击穿）
  - 派发本身要能被审批规则管住（子代理跑 bash 是高危动作）
- 验收：派发 → 子代理独立执行 → 结果回主对话；子代理失败主对话可感知；不占 LRU 额度；大输出被截断且如实标记。

### 4. 多把 API 密钥

同一 provider 持多把 key，按名字寻址。

- 参考：`model-admin.ts` 约 1937 行里的 provider-keys 部分。
- 要点：
  - 存储：`<agentDir>/provider-keys.json`，形如 `{provider: {activeKeyName, keys: [{name, apiKey}]}}`
  - **铁律：原始 key 值与掩码永不出服务端**。任何响应体、日志、错误消息里都不能出现原始 key
  - 沿用 `fileSettingsPort` 的原子写 + 损坏回落语义
  - 「激活哪把 key」要走 `SessionHub.setModel()` 那条单一真源路径，不要绕过（否则 REST 与 WS 会分裂）
  - 明确**不做**：OAuth 流程、provider 配置增删改 UI、连接测试
- 验收：增删查切可用；**任何响应体都不含原始 key**（写测试断言）；切换后实际生效；坏文件回落不崩。

## 五、硬性约束（违反即返工）

### 安全
1. **路径校验一律 fail-closed**。`realpath` 失败就拒绝，不放行。理由：字面路径在目录内 ≠ 真实路径在目录内，符号链接正是把两者分开的机制。参考 `src/files/service.ts` 的 `assertRealpathInside()`。
2. **不要重复实现 SDK 已有的路径/ID 逻辑**。会话目录要问 SDK（`SessionManager.create(cwd).getSessionDir()`），不要自己复现它的 cwd 编码规则——分叉了会静默失效。
3. **新增对外端点一律用 `AppError`**，不要手写 try/catch 拼响应。`internal` 类默认隐藏内部细节。
4. **限流**：新增重资源端点要加进 `DEFAULT_RATE_RULES`。探针类不限流。

### 测试
5. **等条件，不要等固定时长**。用 `src/test-server.ts` 的 `waitFor(谓词, "说明")`，**禁止** `await sleep(300)` 这类拍脑袋的等待——它在全量并发时会偶发失败，然后被误判成「和改动无关」（这个坑已踩过一次）。
6. **测试必须真能捕获它声称防的东西**。新增测试后做一次**反向验证**：把实现改回缺陷形态，确认测试变红，再改回来。
7. 不依赖网络与 API Key，用替身驱动真实编排栈（参考 `src/integration.test.ts` 的 `FakeSession`）。

### 门禁（每一步都必须全绿）
```powershell

```
