What it solves

A runnable skeleton, not a demo

The SDK's createAgentSession is wrapped once into buildAgent(); HTTP+SSE, WebSocket, an in-process CLI and the official RPC stdio transport all sit behind that single core.

Vertical by injection, not by fork

Business logic enters through extraTools, extraSkillPaths, extraKnowledgeDirs, extraExtensions. User-level ~/.pi scanning stays off, so nothing leaks into a deployed agent.

Safety is a first-class axis

Three built-in-tool tiers, a fail-closed path guard, read-only SQL, and an approval gate whose deny rules cannot be overridden and whose timeout closes the turn.

What stands out

  • One buildAgent() core behind CLI, HTTP+SSE, WebSocket, library and official RPC.
  • Pluggable RAG: zero-dependency keyword search, opt-in vector retrieval with swappable embedder and store.
  • Approval gate with non-overridable deny rules, a watchdog, and cross-session memory at owner-only file modes.
  • MCP bridge, plan mode, subagents, web tools, process execution — all optional, all injectable.
  • Docs are code: every number on this card is generated from source and re-checked in CI.
