## 1. 两边各自是什么

**pi-starter** 是垂直 Agent 的起步模板，不是编码助手。CLI、HTTP、库三种形态共用 `buildAgent`。业务从接口注入（工具、技能、扩展、人设），不改内核。运行时依赖尽量只留 SDK、Express、TypeBox、`ws`；环境变量用 Node 内置加载，数据库用 `node:sqlite`。

五条不要破的原则：

| 原则 | 含义 |
|---|---|
| 通用内核，不做成编码专用 | 按「任何垂直 Agent 都需要」取舍，不按「能改代码的驾驶舱」取舍 |
| 零重依赖优先 | 能用 Node 内置就不加包 |
| 可注入、可裁剪 | 能力是可替换的函数或参数，不长成万行单文件 |
| 默认安全 | 默认 loopback、编码工具默认关、`deny` 规则关不掉 |
| 核心逻辑可单测 | 评估、校验、协议翻译不碰网络、不调模型 |

**pi-web-ui** 是生产级 AI 编码驾驶舱：聊天、改代码、文件、终端、git，外加 Electron、桌面 sidecar、双引擎（pi + DeepSeek Harness）。`server/` 约 130 个 TS 文件，最大单文件 `agent-service.ts` 约 1.5 万行。它和我们同源，都坐在 `@earendil-works/pi-coding-agent` 上，所以能对照；它不是「脚手架再加几个工具」的量级。

它值得继承的是骨架思想，不是文件清单：服务端快照是唯一事实源、协议类型只有一份、权威状态和实时增量分成两条通道、审批用声明式规则、设置按字段校验。

## 2. 对方的边界：做到了什么，停在哪里

下面按他们自己的功能域写。每一域只回答两件事：他们做到哪一步，哪一部分是编码驾驶舱专用、我们不跟着长。

| 域 | 他们做到的程度 | 边界 / 不必照搬的部分 |
|---|---|---|
| 协议与传输 | WS 双向；`UiState` 快照 + `rev` 链；增量 delta 绕过背压；Origin/Host 校验；心跳；协议版本协商。客户端命令约 100 个 | 命令里大量是 `terminal_*` / `scm_*` / `plugin_*`。协议落地偏重，不是脚手架需要的面 |
| 会话编排 | 每连接多个对话，每个对话独立 runtime；上限按项目计；跨客户端过户有事务回滚；项目记住模型 | `agent-service.ts` 单文件约 1.5 万行。过户、项目维度是驾驶舱能力 |
| 工具 | 按名覆盖 SDK 内置工具；LSP、哈希补丁、eval、懒加载、看门狗、ActiveSet | 覆盖链直接改 SDK 私有字段 `_customTools`，升级就会碎。LSP / patch / Office 解析是改代码专用 |
| 审批 | 规则库自顶向下首个命中；约 10 条内置高危；allow / deny / ask；对话级三档免问；人可以改参后放行 | 规则匹配含 regex / glob / contains / prefix / outside_workspace。他们有 `plugin:` 档位，我们没有，我们多了 `capability` |
| 运行模式 | 计划模式（硬闸门 + 提示词，约 400 行）；审查委派；目标→执行→审查→修订（`goal-service.ts` 约 2500 行）；子代理 | 目标审查循环和子代理是产品循环，不是地基 |
| 终端与后台任务 | node-pty 七件套；Windows ConPTY 自愈（`terminals.ts` 约 2300 行）；bash 启动的监听进程可列出、停止 | PTY 在 Windows 上坑很深，他们用整文件才稳住。脚手架阶段不进内核 |
| 文件与附件 | 文件 CRUD、预览、Range、上传；附件只给路径不灌进上下文；视觉模型转写；归档拒绝符号链接和设备文件 | 视觉桥、Office 解析、CAS 附件是编码/多模态驾驶舱的装备 |
| 模型 | 运行中切换；一个 provider 多把 key，原始 key 不出服务端；OAuth（`flowId + promptId`，令牌不进 wire）；自定义 provider 的增删和测连（`model-admin.ts` 约 1900 行） | 多密钥和「密钥不回传」值得学。1900 行的管理台不要整包搬 |
| 扩展 | MCP：外部 stdio 工具接入，改配置不用重启（约 600 行）。插件：市场、安装、两步授权、宿主 API、slot、定时任务（`plugins.ts` 约 4700 行） | MCP 覆盖「接外部工具」。插件市场是他们第二大子系统，放最后 |
| 上下文与提示词 | 按 token 分层裁剪、软上限、压缩、悬空 tool call 修复；提示词 11 个 token 可逐层覆盖 | 思想我们已经有一版（预算 + 模板）。他们多的是主动压缩工具和更多层 |
| 安全与运维 | 默认 loopback；token 鉴权；quiesce 拒绝新工作；控制 socket；更新检查；Electron；Docker / systemd / launchd | 我们刻意不做登录和多用户。鉴权、桌面端、发布体系是产品层 |
| 第二引擎 | DeepSeek Harness，JSON-RPC，和 pi 引擎并存（约 5000 行） | 与脚手架无关 |

他们**没有**、而我们有的，主要是：只读 SQL 工具、Markdown 知识库检索、类型化错误（`internal` 默认不把原文回给客户端）、`/metrics` 和脱敏日志。这些不要为了「对齐」删掉。

他们能力分布不均：最厚的是会话编排、插件、第二引擎、目标审查、终端、模型管理。会话持久化、SQL、知识库这类基础面他们反而薄。照着行数抄，会把失衡一起抄进来。

## 3. 我们现在有什么

以下是 `c60b282` 上核对过的，不是早期快照。

**骨架（已经和对方同构，不再是缺口）**

- WebSocket 双向、快照 + `rev` 链、增量 delta、背压下丢快照、慢客户端持续背压会断开。
- `protocol.ts` 是消息类型单源，内置命令有编译期完备性断言。
- 多对话：每个对话独立 session，有上限和 LRU。没有项目维度，没有跨客户端过户。
- 工具注册表带能力标签，运行中可以开关。不改 SDK 私有字段。
- 工具看门狗：超时中止；正在等人类的工具不计时。
- 审批：10 条内置高危规则，六种匹配器全部有（`regex` / `glob` / `contains` / `prefix` / `outside_workspace` / `capability`），三档策略，人可以改参后放行。`deny` 不能被「关掉审批」绕过。
- 上下文预算和提示词模板。层数比对方少。
- `run_start` / `run_end`（带 `stopReason`，能区分将重试和被中止）/ `tool_delta`。
- 传输：Origin/Host 校验、body 上限、安全响应头、限流、只读 SQL（CTE 里的写也会拦）。

**这一轮新接上的**

- 自定义 WS 命令：把 `commands` 传给 `attachWebSocket`。没有 `registerCommands()` 这个函数。`defineCommand()` 只在编译期给 `payload` 标类型，**运行时不校验**。未注册命令回错误帧，帧里列出的是已注册的自定义命令，不是内置全集。同名注册盖不住内置命令。
- HTTP：`createApp({ configure })` 在错误处理器之前注入业务路由。`internal` 不把密码、绝对路径、堆栈回给客户端。
- `addDisposer()`：停机时回收，单个清理失败不挡住其余的。
- 文件服务：列出、读、写、新建、改名、复制、删除、原始内容、上传。字面路径必须在工作目录内；符号链接用 `realpath` 再查一次，**解析失败就拒绝**。整条路径都不存在时（新建文件）只做字面校验，因为没有可逃逸的实体。
- 设置落盘：原子写。JSON 解析失败回落默认值。字段未知或类型不对时剔除并告警，服务仍能起来。通过 API 改设置仍然拒绝未知字段，而且每次 `patch()` 都写盘。
- 审批规则落盘：启动时读，非法规则跳过（`value` 必须是非空字符串，`outside_workspace` 除外），内置 `deny` 还在。**只在优雅停机时把内存里的规则写回。** 没有编辑 API，`upsert` / `setUserRules` 只在测试里被调用。

**入口上仍然在的**

- CLI 流式对话；HTTP 资源接口不调模型，`/chat` 仍是 SSE。
- 技能（仓库内 `SKILL.md`，不扫 `~/.pi`）、Markdown 知识库（按关键词，不是向量库）、sqlite 只读查询。
- 模型目录、启动时选择、运行中 `setModel`（REST 和 WS 走同一个 hub）。没有多密钥，没有 OAuth。
- 编码工具三档 `off` / `readonly` / `coding`，默认 `off`。
- `npm run setup` 把 provider 写进 `~/.pi/agent/`，密钥文件权限收紧。不覆盖已有密钥，除非 `--force`。

**刻意不做**

登录、多用户、向量库、真沙箱、公网无鉴权暴露、PTY、插件市场、第二引擎、Electron、定时任务、支付、产品 UI。

非 loopback 必须自己加鉴权代理。本项目不内置登录，这是定位，不是遗漏。

## 4. 对照：他们有什么，我们有什么

| 能力 | 他们 | 我们 | 取舍 |
|---|---|---|---|
| 快照 / 协议 / 多对话 | 有，且带项目与过户 | 有，无项目、无过户 | 骨架对齐。过户先不做 |
| 工具注册 | 硬编码目录 + 改私有字段 | 数据驱动，走公开 API | 保持我们的，不要退回私有字段 |
| 看门狗 / 审批规则 | 有 | 有，匹配器已齐 | 对齐。缺的是规则编辑入口，不是匹配器 |
| 轮次信号 | `agent_end` 汇成结束信号 | `run_start` / `run_end` / `tool_delta` 已有 | `entry_appended` 只刷新标题，没有对应协议帧。`turn_start` / `turn_end` 还没有 |
| 文件 | CRUD + 预览 + Range + 归档 + 视觉 | CRUD + 预览上限 + 符号链接 fail-closed | 手已经有了。视觉桥、归档、Office 先不做 |
| 模型 | 多密钥、OAuth、管理台 | 目录 + 切换 | 下一步只做多密钥，不做整座管理台 |
| 会话是否活过重启 | 有客户端状态落盘 | 设置能活过重启；**Web 对话不能**；规则只有停机才写 | 这是当前最实的缺口 |
| MCP | 有，改配置可热生效 | 无 | 符合「能力从外面注入」，优先于插件 |
| 计划模式 | 有，约 400 行 | 无 | 成本低，让行为可控 |
| 子代理 / 目标审查 / SCM / 后台任务 / PTY / 插件 | 有，而且厚 | 无 | 等业务真的需要再做，不按他们的行数排期 |
| SQL / 知识库 / 指标 / 类型化错误 | 基本没有 | 有 | 保留 |

## 5. 下一步：我们自己要长什么

顺序按「脚手架缺了就接不进去」，不按对方文件有多大。

**1. Web 会话持久化**

设置已经能活过重启，对话不能。CLI 侧 SDK 的 `SessionManager` 已经会落盘，Web 侧还是内存。做到：重启后能恢复这个工作区里的对话列表和内容。不做跨客户端过户，不做按项目分库。对方那 1400 行客户端状态里，后半是驾驶舱的账，不要一起搬。

**2. 规则的编辑入口，以及一改就写盘**

这是把已经做了一半的持久化收完，不是新功能。现在没有 HTTP / WS 可以改规则。进程崩溃不会把磁盘上的手改写丢（崩溃时根本不写）；**优雅停机会用启动时读入的内存副本覆盖磁盘**，运行期间改过的文件会被写回去。做到：有明确的读改接口，改完立刻原子写，重启还在；停机写回不能盖掉进程启动之后的外部修改，除非那次修改来自我们自己的接口。

**3. MCP 桥**

外部 stdio 工具进会话，改配置不用重启。这和「业务从接口注入」是同一件事。插件市场先不做。

**4. 计划模式**

会话级「只规划、不写」。写类工具被拒，并给出能看懂的原因。审查委派和目标循环先不做。

**5. 多把 API 密钥**

按名字保存、切换当前使用的那把。任何响应里不出现原始 key。OAuth 先不做，除非真有一家 provider 必须走浏览器登录。不要把 `model-admin.ts` 整文件搬过来。

**先不做**

SCM、后台任务跟踪、子代理、附件与视觉、`turn_start` / `turn_end`、插件系统、PTY、第二引擎、桌面端、定时任务、登录。

斜杠命令里那 4 条内置项仍是硬编码。可以以后从已有命令推导，不是缺口。

每做完一项跑：

```powershell
npm run verify
npm run lint:unused
```

新测试要能在改回缺陷时变红，不能只在修好的代码上是绿的。

## 6. 复核时钉死的事实

这些曾经被说错，留在这里是为了不再从旧稿里抄回去。

| 事实 | 不要再说成 |
|---|---|
| 扩展点是 `attachWebSocket(..., { commands })` | 不存在 `registerCommands()` |
| `defineCommand()` 只给编译器看 | 它不会在运行时挡住非法 payload |
| `entry_appended` 只刷新标题 | 它不是和 `run_end` 并列的前端信号 |
| 规则没有编辑 API，只在停机写回 | 「避免 API 编辑丢失」这条路径不存在 |
| 设置：解析失败回落；字段非法则剔除。API 仍拒绝未知字段 | 「文件坏了都能起来」曾经没覆盖字段非法，服务会起不来。这一点已修 |
| 规则的 `value` 必须是非空字符串 | 缺 `value` 的 glob 会在匹配时抛；缺 `value` 的 regex 会去匹配字面量 `undefined`。已修 |
| `realpath` 失败就拒绝 | 失败时放行是错的：字面路径在目录内，不等于真实路径在目录内。已修 |
| 六种匹配器在持久化那笔提交之前就有 | 「缺 glob / contains / prefix」是照文档推测的 |

`c60b282` 的提交说明后半段仍粘着上一笔的旧文字，里面还有「避免通过 API 做的编辑丢失」。以本节和源码为准，不以那段提交说明为准。
